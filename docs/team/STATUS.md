이 문서는 2026-11-27까지 확인한 기록의 요약이다. 진행 중인 현장 시험 결과는 담당자의 완료 보고 후 갱신한다. 이 저장소와 실제 장비에 설치된 파일의 동등성은 입증되지 않았다.

## 재현성 차단

현장 q13/C103 배포 계열은 로컬 보관 자료 및 장비 설치본에 의존하며 Git에 완전하게 포함되지 않았다. Base r3, Astra 수정·계측 후보, low-load overlay와 최신 18190 운영 설정도 동등한 소스·설정·의존성·버전 조합이 이 브랜치에 있다고 검증하지 못했다. 제삼자 소스의 라이선스, 수정 내역 및 공개 범위를 확인하기 전 임의 복사하지 않는다. 현장 기록과 후보의 hash, 라이선스, 누락 의존성, build 및 복구 검증을 함께 정리해야 한다.

## 주행 차단

비정상 전원 정지/재부팅 원인 미확정, STM32 명령 timeout·부분 프레임 동작 미확인, Base STALE과 비정상 종료의 안전 계층 대응 및 `/odom` 시각 호환성 미검증, 카메라 TF 실측·LiDAR costmap 검증 미완료, 독립 비상정지와 제동 경로 검증 부족, 지도 unknown 보존 문제 등이 남아 있다. 1.25초 Depth timeout과 Safety READY 조건을 임의로 완화하지 않는다. 현장 운영자는 물리적 정지 수단과 추락 위험 차단을 확인하고 각 시험과 주행에 대해 별도 승인을 받아야 한다.

기존 참고: [실차 현황](../REAL_ROBOT_STATUS.md), [웹 Mapping 기록](../../fleet_control/docs/WEB_MAPPING_20261119.md), [통합 운영 가이드](../INTEGRATED_AUTO_MAPPING_OPERATIONS_GUIDE.md). 날짜가 오래된 문서의 성공·명령·절대 경로는 현재 운영 승인으로 해석하지 않는다.

## 2026-11-27 Git 기준선의 독립 복제 점검

원격 `main`의 `e1f8f303`을 독립 복제하고 하드웨어 없이 검사했다. 패키지 목록은 조회됐다. ROS Humble 환경에서 두 패키지만 `--packages-select`로 빌드한 시도는 `limo_depth_obstacles` 성공 후 `limo_capstone`이 작업공간 내부 의존 패키지의 설치 파일을 찾지 못해 실패했다. `--packages-up-to` 시도도 `ydlidar_sdkConfig.cmake` 부재로 실패했고 의존 작업 두 개가 중단되었다. 이 환경에서 전체 빌드·launch plan·지도 재로드는 확인하지 못했다.

웹 Mapping/지도 Registry 테스트는 **38 PASS, 7 SKIP, 1 FAIL**이다. 실패는 시험에서 `limo_rmf_real.map_identity`를 가져오지 못한 것이다. 현재 원인이 소스 누락인지 시험 경로 문제인지 확정하지 않았다. 이 수치는 로봇이나 웹 화면의 동작 성공을 의미하지 않는다. 의존성 설치, 완전한 Mock 흐름, 지도 저장 및 재로드는 추가 검증이 필요하다.

## 과거 실차 구성과 현재 후보의 차이

11/19 실차 기록은 F4, scan normalizer, 차동 저속, LiDAR, Depth 640×400·15 Hz, 별도 XYZ, Depth `required`·1.25초 및 Fixed2 memory를 사용했다고 기록한다. 임시 launch와 설치본이 포함되어 현재 Git 버전과 동일하지 않다. 저장 지도와 posegraph가 남았지만 Frontier가 남은 상태에서 탐색이 멈췄다. 또 다른 잠금 시험은 LiDAR-only였다. 당시 정확한 Git commit과 임시 launch의 완전한 재현 가능성은 현재 확정하지 못했다.

현재 저부하 후보는 Depth-only, 프로세스별 BLAS 스레드 제한과 16 MiB SHM, Base r3, C2 및 Agent 후보를 포함하는 별도 조합이다. 구성 요소별 시험과 전체 조합 검증을 혼동하지 않는다.
