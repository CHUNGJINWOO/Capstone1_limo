# 구성과 알고리즘

구성은 버전별로 다르다. 다음은 코드와 기록에 나타난 역할이며, 한 프로세스 조합이 모두 실차 검증됐다는 뜻은 아니다.

```text
LiDAR → scan 정규화 → F4 ICP odom ─┐
                                   ├→ TF → SLAM Toolbox → 지도 → Frontier 목표
Depth → XYZ → 높이 필터 ──────────┤                       ↓
                                   └→ costmap ← Nav2 계획·제어
                                           ↓
                         명령 중재 → Watchdog → Safety Gate → Base
```

- **SLAM Toolbox:** 스캔과 자세의 관계를 이용해 지도와 `map → odom`을 갱신한다. raster 지도와 posegraph는 다르며 저장·재로드를 각각 확인한다.
- **ICP:** 연속 LiDAR 스캔의 대응점을 정합해 상대 움직임을 추정한다. F4는 2D LiDAR odometry 경로다. 특징이 적거나 미끄러지면 오차가 커진다.
- **EKF:** 시간에 따른 상태 예측과 센서 측정의 불확실성을 결합한다. ICP는 스캔 정합이고 EKF는 여러 측정의 융합 방식이다. F5 후보는 ICP와 IMU를 결합하며, 최근 저부하 후보는 F4를 유지한다.
- **Frontier:** 알려진 빈 공간과 미탐색 공간의 경계에서 다음 탐색 후보를 고른다. 후보가 없다는 것은 전체 지도가 정확하거나 완성됐다는 증거가 아니다.
- **A*·Nav2:** A*는 비용 격자에서 경로 후보를 찾는 방법이다. Nav2는 전역 계획, 지역 제어, costmap과 목표 관리를 묶는다. 선택된 planner는 실행 설정으로 확인해야 한다.
- **Depth 필터:** 점군을 기준 좌표계로 변환하고 높이·영역을 걸러 장애물 점을 만든다. 카메라 높이·각도와 데이터 신선도가 정확해야 한다.
- **Fixed2:** 관측한 장애물을 잠시 기억해 가림이나 일시적인 센서 누락에 대응하는 구성이다. 물리적 낙하 방지나 충돌 방지의 보증은 아니다.
- **TF:** `map → odom → base_footprint → base_link → sensor` 같은 좌표계 사이의 시간에 따른 변환이다. 각 변환의 발행자는 하나여야 하고 높이·각도 단위와 시각을 확인한다.
- **Safety Gate:** 센서 신선도와 장애물·정지 조건에 따라 속도 출력을 제한하거나 차단한다. 장애 발생 시 명령이 실제 바퀴에서 멈추는지 별도 검증이 필요하다.
- **Motion Watchdog:** 권한·상태·명령의 유효성을 감시한다. Gate, Base, STM32 timeout은 서로 다른 계층이다.
- **Velocity Arbiter:** 여러 명령 출처의 소유권·우선순위를 조정하는 구성이다. 배포 조합마다 포함 여부가 다르므로 임의로 명령 토픽을 직접 발행하지 않는다.

웹 제어, 분산 Edge–Central 구조와 추가 안전 기능은 각각 해당 구현과 검증 상태를 [기준선](STATUS.md)에서 확인한다.
