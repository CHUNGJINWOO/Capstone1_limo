# 개발 상태와 다음 구현 과제

기준: 2026-10-25 문서 정리. LIMO 보고서·지도·영상과 2026-10-24 Gazebo 시험을 구분한다. 이번 저장소 정리는 새로운 로봇 주행 시험이 아니다. 과거 설계·설정은 Git 이력에 남아 있다.

## 조사하면서 배운 점

- 토픽 이름이 보여도 센서 데이터를 받는 것은 아니다. 발행·구독 QoS와 수신 상태를 함께 확인한다.
- 노드 프로세스의 실행과 Lifecycle의 Active 상태를 구분한다. 지도 미수신에서는 Lifecycle과 지도 수신 QoS를 각각 조사한다.
- 정적 TF의 `view_frames` 표시값 10000을 실제 10kHz 통신·계산 성능으로 인용하지 않는다.
- 프론티어의 평균점과 로봇에 가까운 경계 셀은 서로 다르다. 목표·제외 목록의 기준을 수정한 사실과 탐색 안정성의 입증은 구분한다.
- Nav2의 성공 반환, Gazebo 위치 기반 도착 오차, 평면 형상 간격은 별개다. 하나의 성공 상태로 안전한 주행 완료를 주장하지 않는다.
- USB 단절·포트 변경은 기록돼 있지만 전압 파형을 측정하지 않았다. 저전압에 따른 전원 강하는 원인 후보이며 하드웨어 원인 확정은 보류한다.

## 다음 기능의 구현·검증 방법

| 개발할 기능 | 구현 접근 | 확인할 동작 |
|---|---|---|
| 순찰·목적지 안내 | 경유지·목적지를 Nav2 목표로 전달하고 응용 노드에서 성공·실패·취소 상태 처리 | 지정 구역 순환, 요청·도착·중단 처리 |
| 안전 감시·속도 중재 | Nav2 Collision Monitor의 감속·정지 영역과 Velocity Smoother 적용 검토, Nav2 재계획과 연결 | 장애물 출현·근접·완전 차단을 나눠 정지·우회·재개 확인 |
| 자동 맵핑 안정화 | 목표 전환·제외 목록·종료 조건 점검, 남은 미지 영역과 중단 원인 기록 | 도달 불가 목표 처리와 복도 탐색 반복 시험 |
| 판정 정합 | Nav2 성공 시각의 map→base_link TF와 Gazebo 위치를 같은 시각에 기록 | 위치 기준 차이·시간 지연·공차 적용을 구분 |
| LIMO 통합 시험 | 센서·지도·위치추정 준비 상태를 확인한 뒤 목표 전송, 성공 횟수·오차·간격 계측 | 반복 주행·정지·재개·장시간 운용 |

Collision Monitor·Velocity Smoother는 구현 후보다. 프로젝트의 안전 중재 구조에 통합해 시험한 상태로 설명하지 않는다. 이전 문서의 `obstacle_detector.py`, `obstacle_controller.py`, `patrol_limo.py`, `guide_limo.py` 예시는 구현 완료 코드가 아니다. 수치 목표는 시험 환경·구동 모드·판정 기준을 정한 뒤 별도 수립한다.
