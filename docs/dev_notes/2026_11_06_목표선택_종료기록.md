# 자동 맵핑 목표 선택·종료 기록 추가

2026-11-05 시작, 2026-11-06 최종 검사 완료. 같은 작업의 보관 위치는 시작 날짜 폴더인 `notebook/2026_11_05/07_목표선택_종료기록/`으로 유지했다.

## 요청과 구현

도달하기 어려운 목표의 대안 선택과, 자동 맵핑이 왜 끝났는지 남기는 기능을 요청받았다. 기존 04번 운영 소스를 복사해 수정했다.

- 같은 프론티어 그룹에서도 떨어진 free 셀 후보를 최대 3개 제공하고 방향·실패 이력으로 순위를 조정한다.
- 실제 주행 전 ComputePathToPose를 비동기로 요청해 경로 끝점·좌표계·비용을 확인한다. 도착 방향은 경로 끝 구간 방향으로 설정한다.
- 변위 없는 성공은 실패 횟수에 포함하고, 목표 좌표가 조금 바뀌어도 주변 이력을 공유한다.
- 사용자 취소·탐색 완료·후보 소진·시간 초과·건강 검사 실패·탐색 오류·저장/정리/기록 실패를 구분한다.
- Action Result에 `termination_reason`, `event_log_path`, `summary_path`, `explorer_log_path`를 추가했다.
- 이벤트 JSONL, 최종 요약 JSON, 탐색 stdout/stderr를 지도 prefix 옆에 저장한다. 관련 ROS 노드의 WARN 이상도 사건으로 수집한다.

콜백은 응답을 받는 함수이고, 이벤트는 그때 발생한 일을 나타내는 기록 데이터다. 응답·결과·취소·rosout 콜백에서 이벤트를 만들고 서버가 파일을 저장하도록 구성했다.

## 검증

두 패키지 빌드 완료, 검사 62개 통과, 별도 실제 ROS Action 통신 검사 1개 통과. 기존 원본 20개 파일의 해시를 보존했다.

Gazebo에서 후보 선택·경로 검사·부분 지도 저장·사용자 취소·밀집 시작 오류와 로그 경로 반환을 확인했다. 초기 로그 콜백 자료형 오류, Nav2 기동 timeout, 중간 버전 실행도 그대로 보존했다. 마지막 로그 순서 보호 수정은 회귀 검사와 실제 ROS Action 통신으로 재확인했으며 Gazebo는 다시 실행하지 않았다.

**책상 근처 이동 정체 자체는 해결되지 않았다.** 여러 목표와 Navfn 경로가 있어도 Ackermann/DWB 주행이 가능한 것은 아니므로 조향·controller 반응을 더 조사해야 한다. 유리·보강대·동적 장애물 costmap 반영·실물 주행은 이번 수정의 해결 결과가 아니다.
