# 2026-11-12 실차 SLAM 스캔 정규화: 최소 배포와 모터 잠금 검증

## 문제

실차 자동 맵핑 시험(11/11)에서 로봇이 2 m 이상 움직였는데도 SLAM Toolbox의 `/map`이 한 장에서 멈췄다. 상세 조사는 `experiments/safety_gate_verification_20261110/slam_scan_fix_20261111/REPORT.md`에 있다.

## 원인 후보와 근거 (이전 조사)

- slam_toolbox(Karto)는 처음 처리한 스캔의 읽기 개수를 기대값으로 고정하고, 개수가 다른 스캔을 거부한다.
- YDLidar 드라이버(`fixed_resolution: false`)는 회전마다 242~245개를 낸다. 시작 직후 첫 스캔은 233~236개였다.
- 이번 시험에서도 원본 `/scan`의 빔 수가 매번 달랐다(아래 표).

## 해결: 정규화 노드와 launch 옵션 (1차, 최소 배포)

- `limo_scan_normalizer` 패키지: `/scan`을 244빔 고정(nearest-beam)으로 다시 발행해 `/scan_slam`으로 낸다.
- 실차 launch에 `scan_normalizer` 인자(기본 `false`)를 추가했다. `true`일 때만 정규화 노드를 띄우고 slam_toolbox의 `scan_topic`을 `/scan_slam`으로 바꾼다. Nav2, F4 추정기, 안전 게이트는 계속 원본 `/scan`을 쓴다.
- 결정 이유: SLAM 입력만 바꾸면 Nav2·게이트의 센서 경로가 달라지지 않는다. 드라이버 설정(`fixed_resolution`) 변경은 팀 원본 패키지를 건드리고 `/scan` 전체를 바꾸므로 택하지 않았다.
- 배포 범위는 LIMO overlay 워크스페이스에만 적용했고, 변경 파일은 launch 1개와 신규 패키지 8개 파일이다. 같은 날 준비한 31개 묶음 중 Safety Gate 래치 수정, PR #8 자동 탐색, 새 BT, RPP 값 변경은 이번에 제외했다(별도 단계로 배포·검증).

## 배포 절차와 보존 (실제 수행)

- 팀 원본 워크스페이스는 읽기만 했다. 배포 전후 파일 수(src 5395, install 545)와 가장 최근 수정 시각이 같았다.
- 배포 전에 overlay의 launch(src와 install)를 홈 아래 `deploy_backup_20261112/`에 백업하고 체크섬(`MANIFEST.sha256`)과 `ROLLBACK.txt`를 남겼다.
- `rsync -av`(`--delete` 없음)로 전송했고, 드라이런과 같은 파일만 전송됐다. 전송 후 체크섬 9개가 모두 일치했다.
- 빌드는 `limo_scan_normalizer`와 `limo_capstone`만 했고 둘 다 성공했다. 팀 install의 `limo_capstone`을 overlay가 덮어쓴다는 colcon 경고는 이전 overlay 빌드와 같은 구조다.
- 복구: 백업한 launch 두 개를 원래 위치로 복사한다(`ROLLBACK.txt`). 신규 패키지는 추가 전용이며 `scan_normalizer`가 `false`인 동안은 아무것도 참조하지 않는다.

## 검증

### 오프라인

- launch 인자를 평가해 기본값과 `false`일 때 SLAM 입력이 `/scan`, `true`일 때 `/scan_slam`임을 확인했다.
- 기존 launch와 새 launch의 엔티티를 비교하면 추가된 것은 인자 1개와 노드 1개뿐이었고 순서는 같았다. 모터 출력 경로(`allow_motor_drive`, gate 출력, `/cmd_vel_raw`, `SetRemap`) 관련 라인의 해시는 백업과 동일했다.
- 정규화 코어의 단위 시험 6개가 통과했다(순수 Python).

### 실차, 모터 잠금

조건: `allow_motor_drive`는 기본값(`false`), `start_explore` `false`, 깊이 카메라 끔, 사람이 입회, 자동 종료 `timeout` 적용. 로봇은 모터가 잠긴 상태에서 사람이 손으로 밀었다.

서 있는 상태(각 25 s):

| 항목 | `scan_normalizer` false | true |
|---|---|---|
| `/cmd_vel` 발행자 | 0 (구독자 `limo_base`) | 0 |
| `/cmd_vel_locked` 발행자 | `stall_detector_node` | 같음 |
| `/cmd_vel` 메시지 / 0이 아닌 잠금 명령 | 0 / 0 | 0 / 0 |
| 게이트 상태 | NORMAL | NORMAL |
| SLAM `scan_topic` | `/scan` | `/scan_slam` |
| `/scan_slam` | 없음 | 233개 모두 244빔 (원본 `/scan`은 241개) |

손으로 밀기(각 70 s). 첫 `false` 시도는 odom 이동이 0.0 m라 비교에서 뺐고, 두 번째 시도만 사용했다.

| 항목 | false | true |
|---|---|---|
| 이동 (wheel odom) | 0.92 m | 1.06 m |
| 최대 속도 | 0.124 m/s | 0.062 m/s |
| SLAM 입력 빔 수 | 244: 585, 245: 114, 242: 3 | 244: 702 (전부) |
| 지도 알려진 셀 | 685 → 685 | 701 → 7531 |
| Karto 빔 개수 경고 | 5건 | 0건 |
| `/cmd_vel` 메시지 / 잠금 명령 | 0 / 0 | 0 / 0 |
| 게이트 | NORMAL, FAILSAFE 0 | NORMAL, FAILSAFE 0 |

- 두 조건 모두 종료 후 ROS·모터 프로세스는 남지 않았다.

## 판단

- 확인됨(실차): 같은 종류의 직진 이동에서 정규화를 끄면 지도가 늘지 않았고 Karto 경고가 났으며, 켜면 지도가 약 10배로 늘고 경고가 없었다. 빔 수 변동이 지도 정체의 원인이라는 설명과 일치한다.
- 이 결과는 각 조건 1회의 수동 시험이고 밀기 속도가 달랐다. 원인을 확정하는 증거로 쓰지 않는다.

## 남은 한계와 미검증

- 회전 중, 긴 주행, 루프 폐쇄에서의 지도 품질과 지도 정확도는 평가하지 않았다.
- 모터가 구동되는 동안의 동작과 자동 탐색과의 결합은 확인하지 못했다.
- `true` 서 있는 실행에서 `/scan` 241개, `/scan_slam` 233개로 8개 차이가 났다(손으로 민 실행에서는 둘 다 702개). 정규화 노드는 코드상 받은 스캔을 모두 다시 발행하므로 원인은 구독 시작 시점 등 측정 쪽일 가능성이 있으나 확인하지 못했다.
- 정규화 패키지의 라이선스 표기는 저장소 기준 `TODO: License declaration`이다. 저장소에 반영할 때 정해야 한다.
- 이번 변경은 LIMO overlay와 노트북 스크래치에만 있고 저장소에는 아직 반영하지 않았다.
