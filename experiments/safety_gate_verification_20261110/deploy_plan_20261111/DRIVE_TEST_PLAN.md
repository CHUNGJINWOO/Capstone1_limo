# 모터 구동 시험 계획 (계획만, 미실행)

상태: **계획만 작성했고 아무 단계도 실행하지 않았다.** `allow_motor_drive:=true`로 launch한 적이 없다. 각 단계는 사용자의 명시적 "go" 뒤에만 하고, 한 단계의 통과가 다음 단계의 승인을 뜻하지 않는다.

## 1. 현재까지 확인된 것과 아닌 것

| 구분 | 내용 |
|---|---|
| 확인됨 (실행) | 잠금 상태 라우팅(`/cmd_vel` 발행자 0, `/cmd_vel_locked` 발행자는 gate), `use_sim_time` false, `motion_mode` 0(4WD 차동), 차동 Nav2 설정 적용(BT 기본 트리, `use_rotate_to_heading` true), 센서 `/scan` 10 Hz·`/odom` 50 Hz |
| 확인됨 (벤치, 바퀴 띄움, 무부하, 0.10 m/s 직진) | 명령이 끊기면 약 0.4 s 안에 정지(`/odom` 측정, 3회). `limo_base`가 SIGINT·SIGKILL로 죽어도 육안 1초 이내 정지(MCU 쪽 명령 타임아웃일 가능성이 높음, 확정 아님) |
| 확인 안 됨 | gate가 실제 휠 구동 중에 정지·래치를 올바르게 수행하는지, 지상 주행, 회전, 고속, Nav2 목표 주행, BackUp 후진의 안전성, 실차 SLAM/지도 품질, F4가 벽과 평행하게 달릴 때의 실패(sim에서만 확인) |
| 알려진 결함 | `limo_base`가 종료 때 abort(-6, 스레드 미정리). `require_operator_unlatch`가 real launch에서 False라 래치가 자동으로 풀리는지는 미확인 |

## 2. 위험과 대응

| 위험 | 대응 |
|---|---|
| gate가 F4(LiDAR odom)에 의존하는데 F4는 벽과 평행하게 달릴 때 이동량을 놓친다(sim 검증) | 초기 지상 시험은 **긴 직선 벽이 없는 열린 공간**에서만. 벽 평행 시험은 마지막에 별도 단계로, 결과 판단 전에 F4 개선 여부를 먼저 정한다 |
| 후진(BackUp)은 후방을 충분히 보지 못할 수 있다 | 초기 지상 단계는 `drive_mode:=ackermann`(후진·Spin 없는 BT)로 시작하고, 차동 BT(BackUp·Spin 포함)는 별도 단계에서 열린 공간·관측자와 함께 |
| 물리적 정지 vs F4 추정 실패가 gate의 세 신호로 구분되지 않는다(sim 분석) | 가속 시험 전에 D0에서 gate의 실제 반응을 본다. 판정을 gate 하나에만 의존하지 않고 사람이 항상 전원 스위치에 손을 둔다 |
| 첫 구동에서 속도가 크다(기본 `desired_linear_vel` 0.32 m/s, 회전 정렬 0.5 rad/s) | 아래 "결정 필요 1": 초기 단계에서 속도 상한을 낮춘 별도 파라미터 복사본을 쓸지 정한다. 지금 launch에는 속도 상한 인자가 없다 |
| 레이아웃·사람·유리 같은 LiDAR가 못 보는 물체 | 시험 구역에서 사람, 유리, 계단·단차를 제거하고 관측자를 둔다 |
| `limo_base` 종료 시 abort | 구동 시험 종료 순서: 먼저 목표를 취소해 0 속도가 gate를 거쳐 나가는 것을 확인한 뒤 launch를 종료한다. 종료할 때 로봇이 움직이고 있지 않아야 한다 |

- [ ] 배터리 전압 충분, `error_code` 0, `motion_mode` 0.
- [ ] 다른 ROS 프로세스 0개 확인(`ps -eo pid,cmd | grep -E "[r]os2 launch|[l]imo_base"`), `limo_base`는 1개만.
- [ ] ROS 도메인 격리 `ROS_DOMAIN_ID=77`. 팀 원본 `/home/pcu/capstone_ws`는 읽기만.
- [ ] 단계 시작 전 `ros2 topic info /cmd_vel`의 발행자는 gate 하나뿐(Nav2·테스트 노드가 직접 `/cmd_vel`에 발행하지 않는다).
- [ ] 자동 종료 `timeout`(단계별 상한)을 걸어 launch가 무한히 살아 있지 않게 한다.
- [ ] 단계별 로그 보존(LIMO의 `lockedtest_20261111/` 아래 단계별 폴더). 원본 영상·시계열 로그는 저장소에 올리지 않는다(`docs/PUBLICATION_POLICY.md`).

## 4. 단계 (모두 `allow_motor_drive:=true`, 단계마다 사용자 go)

### D0. 바퀴 띄움 + 전체 스택 (지면 접촉 없음)
목적: gate가 실제 휠 구동 중에 정지를 올바르게 수행하는지 본다.
- 바퀴를 띄운 채 real launch를 `allow_motor_drive:=true`로 실행한다(`drive_mode:=ackermann`).
- Nav2 목표를 준다. 바퀴는 돌지만 로봇은 이동하지 않으므로 LiDAR 속도는 0이다.
- 기대: 휠 속도 ≥0.06, 명령 ≥0.075, LiDAR 속도 <0.025가 1.5 s 지속되면 gate가 STALL_PENDING → LATCHED로 가고 `/cmd_vel`이 0이 된다.
- 기록: gate 상태 전이 시각, `/cmd_vel` 0 전환 시각, 바퀴가 멈추는 시간, 래치가 자동으로 풀리는지(`require_operator_unlatch` False), 풀린 뒤 명령이 다시 나가는지.
- 통과: 래치 후 `/cmd_vel`이 0이고 바퀴가 멈춘다. 풀리는 동작이 위험하면(곧바로 재구동) 이 단계에서 중단하고 원인을 먼저 본다.
- 중단: 명령 없는데 바퀴 구동, 래치 없이 계속 구동, 정지 지연 3 s 초과.

### D1. 지상 직진, 짧은 거리 (후진·회전 없음)
- 열린 공간 바닥, 주변 2 m 이상 비움. `drive_mode:=ackermann`.
- 목표: 로봇 정면 0.5 m. 줄자로 실제 이동 거리를 재서 휠 odom·F4 추정과 비교.
- 통과: 목표 도달, 실제 이동 ≈ 추정(허용 오차는 사전에 정한다), gate NORMAL 유지, `/cmd_vel_raw`와 `/cmd_vel` 일치.
- 중단: 의도하지 않은 방향 이동, 예상 거리 초과, gate FAILSAFE.

### D2. 지상 직진 + 정지 확인
- D1과 같은 환경에서 목표 1.0 m. 도중에 목표를 취소해서 정지 시간을 측정한다.
- 통과: 취소 후 정지까지 시간이 gate 타임아웃·MCU 타임아웃(~0.4 s)과 정합.

### D3. 제자리 회전 (차동 BT)
- `drive_mode:=diff`. 목표를 로봇 측면 방향으로 주어 `use_rotate_to_heading`·Spin이 동작하는지 확인. 후진이 일어날 수 있으므로 후방 1 m 비움, 관측자 필수.
- 통과: 제자리 회전이 부드럽게 일어나고 위치 이동이 작다(줄자).

### D4. Nav2 목표 주행 (짧은 경로, 장애물 없음)
- 지도 일부가 SLAM으로 만들어진 뒤 2~3 m 이내 목표. 정상 도달·정지 확인.

### D5. 정적 장애물 회피
- 발포·상자 등 가벼운 장애물을 경로에 둔다. 로봇은 회피하거나 정지해야 한다. LiDAR 높이 밖의 물체는 쓰지 않는다.

### D6. 자동 맵핑(explore) 짧은 시간
- `start_explore` 켜고 열린 방에서 최대 N분(사전 결정). 위험 구간 접근·벽 평행 주행에서 F4/gate 거동을 관찰.
- 이 단계 전에 F4의 벽 평행 문제를 어떻게 다룰지 결정이 있어야 한다.

### D7. (선택) 깊이 카메라 포함
- `use_depth_camera:=true`, `depth_mode:=required`. 본 계획 범위 밖, 별도 계획.

## 5. 각 단계에서 남길 기록
시작·종료 시각, 인자, 환경(사진은 올리지 않음), 배터리 전압, gate 상태 로그, `/cmd_vel_raw`·`/cmd_vel`·`/odom`·`/odometry/lidar_odom` 요약, 줄자 실측 거리, 중단 여부와 원인, 판단(통과/보류). 기록은 검증된 것과 아닌 것을 구분해서 적는다.

## 6. 전체 중단 조건 (전원 차단)
명령 없는 구동, 지정 방향·속도에서의 이탈, 정지 명령 후 3 s 내 미정지, 장애물 접촉, 사람·반려동물 접근, 이상 소음·냄새, `error_code` ≠ 0.

## 7. 결정 필요
1. **속도 상한**: 초기 지상 단계(D1~D4)에서 `desired_linear_vel`을 0.32 → 예: 0.15 m/s 정도로 낮춘 별도 파라미터 복사본을 쓸까요? (launch 수정 또는 새 params 파일 필요, 승인 후)
2. **시험 장소와 관측자**: 실제 사용할 공간, 인원.
3. **D0 래치 해제 동작**: 자동 해제가 위험하면 `require_operator_unlatch`를 켜는 변경이 필요한지(게이트 정책 수정이므로 별도 승인).
4. **F4 벽 평행 문제**를 D6 전에 해결할지, D6을 벽 없는 환경으로 제한할지.
5. 허용 오차(D1, D2의 추정 vs 실측)의 수치.

## 8. 실행 기록

### D0 (2026-11-11) — 의도와 달리 지상 주행이 되었다
- 설정: `allow_motor_drive:=true`, `speed_profile:=slow`, `drive_mode:=ackermann`, 목표 map (0.8, 0.0), ROS 도메인 77, 격리.
- 점검표: 사용자가 "바퀴 4개가 바닥에서 떠 있음" 등 4개 항목을 모두 확인했다고 응답했다.
- 결과(센서 기록, LIMO `lockedtest_20261111/d0/`): 목표 `SUCCEEDED`, 약 5 s 동안 0.15 m/s 명령, gate는 시험 내내 `NORMAL`(stall_events 0), LiDAR 속도가 휠 속도를 따라감.
- 사용자 관찰: **로봇이 실제로 앞으로 움직였다.** 따라서 이 시험은 바퀴를 띄운 D0이 아니라, 지상에서의 0.8 m 직진(D1에 해당)이었다. D0의 목표(gate의 정지 반응 확인)는 달성되지 않았다.
- 확인된 것: 속도 상한 0.15 m/s 유지(휠 최대 0.164), `/cmd_vel` 발행자는 gate 하나, 목표 도달 후 0 속도, 명령 종료 후 휠 정지 약 0.1~0.4 s, 자동 중단 조건 미발동, 종료 후 잔여 프로세스 0.
- 확인되지 않은 것: 실제 이동 거리(줄자 측정 없음, 센서 추정 약 0.7 m), gate의 정지(래치) 동작, 바퀴를 띄운 상태의 거동.
- 교훈: 점검표 응답만으로는 "바퀴가 떠 있다"를 소프트웨어가 확인할 수 없다. 다음 구동 시험 전에 로봇이 움직일 수 없는 상태임을 시험 전에 별도로 확인하는 절차가 필요하다.

### D2 (2026-11-11) — 지상 직진, 진행 중 취소로 정지 시간 측정

- 사전 오류와 정정(중요):
  - gate의 `min_front_scan_m`은 이름과 달리 `/scan` **전체 방향** 최솟값이다(`stall_detector_node.py`의 `cb_scan`). 이를 "정면 거리"로 오해해 두 번 시작을 막았다. 정면은 비어 있었고, 가장 가까운 것은 옆의 물체였다(해당 시점 오른쪽 약 0.9 m).
  - 정면 통로 검사로 교체: 로봇 앞 폭 0.60 m(|y|≤0.30) 안의 가장 가까운 점까지의 x(레이저는 base_footprint 앞 0.103 m, yaw 0, `/scan`은 -110°~+110°라 후방은 보지 못함).
  - 첫 실행(0.6 m, 기록 보류)과 그 다음 실행 한 번은 감시 프로세스가 임포트 오류로 죽은 채 진행되었다(속도 상한과 gate는 유효했지만 자동 중단 감시는 없었다). 이후 스크립트는 감시 프로세스가 살아 있고 기록 중임을 확인한 뒤에만 목표를 보낸다.
- 유효 실행(감시 정상) 결과 — LIMO `lockedtest_20261111/d2/d2b_*`:

  - 속도: `/cmd_vel_raw`·`/cmd_vel` 최대 0.150 m/s, 휠 최대 0.17 m/s. 자동 중단 미발동.
  - 이동: 휠 적분 0.465 m, F4 적분 0.437 m(약 6% 차이). 줄자 실측은 없음.
  - gate: 시험 내내 `NORMAL`, `stall_events` 0. `/cmd_vel` 발행자는 gate 하나.
  - 목표 결과: CANCELED(status 5).
  - 이전 0.6 m 실행(목표 도달로 종료): 휠 적분 0.520 m, F4 0.502 m, 명령 종료 후 휠 정지 0.17 s. 이동 시작 직후 gate가 약 0.03 s `STALL_PENDING`에 들어갔다가 `NORMAL`로 복귀(래치 없음). 휠이 0.1 m/s 이상일 때 LiDAR 속도는 0.028~0.304(중앙값 0.127)로 흔들렸다.

### D3 준비 (2026-11-11, 미실행) — 차동 BT에서 제자리 회전
- 스크립트(LIMO `lockedtest_20261111/d3/`): `run_d3.sh <spin|heading> <라디안> [태그]`, `d3_act.py`(액션 클라이언트), `rec_d3.py`(기록+자동 중단), `corridor.py`. 모두 컴파일/임포트 확인만 했고 launch는 실행하지 않았다.
- 설정: `allow_motor_drive:=true`, `speed_profile:=slow`(회전 상한 0.5 rad/s, 최소 0.2), `drive_mode:=diff`.
- 스톡 BT 복구 순서(참고): Spin 1.57 rad → Wait 5 s → BackUp 0.30 m @ 0.05 m/s. 복구 동작이 저절로 일어나지 않도록 회전은 Spin 액션과 제자리 방향 목표로 직접 시험한다. costmap `robot_radius`는 0.18 m.
- 단계:
  - D3a: `spin` +1.57 rad(왼쪽 90°). 순수 제자리 회전, 선속도 0.
  - D3b: `heading` +1.57 rad. 현재 위치 그대로 목표 방향만 +90° (RPP `use_rotate_to_heading`).
  - D3c(선택): `spin` -1.57 rad(오른쪽). BackUp(후진)은 후방을 못 보므로 이 계획에 넣지 않는다. 필요하면 후방 1 m를 비우고 관측자를 둔 별도 승인 하에서만.
- 시작 전 확인(스크립트): `/cmd_vel` 발행자가 gate 하나, `/scan` 전체 방향 최근접 ≥0.45 m, 감시 프로세스가 기록 중.
