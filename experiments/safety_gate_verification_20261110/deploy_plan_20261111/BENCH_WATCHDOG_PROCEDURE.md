# 바퀴를 띄운 MCU 워치독 벤치 시험 절차 (작성만, 미실행)

> **정리본 상태 (2026-11-11).** **검증 수준:** 바퀴를 띄운 무부하 벤치 1회 실행 기록(결과 칸 작성됨). 육안 측정 포함, 지상 주행 조건은 측정하지 않았다. 이 기록은 당시 설정과 환경에서 얻은 값이며 이후 정리된 파일 이름·값으로 다시 측정한 것이 아니다. 전체 목록: `experiments/README.md`.

상태: **작성만 했고 실행하지 않았다.** 아래 결과 칸은 모두 비어 있다. 이 시험은 모터를 구동하므로 사용자가 현장에서 직접 진행하거나 지켜보는 경우에만 한다.

## 1. 무엇을 알아내는가
소스(`limo_driver.cpp`)에는 명령이 끊겼을 때 0 속도를 보내는 타이머가 없고, 종료 때 정지 프레임도 보내지 않는다(소멸자가 비어 있고 `limo_base`는 SIGABRT로 끝난다). 따라서 안전 여부는 로봇 MCU 쪽 동작에 달려 있고 소스로는 알 수 없다. 이 시험은 다음 세 가지를 측정한다.

| 질문 | 시험 |
|---|---|
| A. `/cmd_vel` 발행이 끊기면 MCU가 스스로 멈추는가, 멈춘다면 몇 초 뒤인가 | T2 |
| B. `limo_base`가 SIGINT(정상 종료, 지금은 abort -6)로 죽을 때 바퀴가 멈추는가 | T3 |
| C. `limo_base`가 SIGKILL로 죽을 때 바퀴가 멈추는가 | T4 |

## 2. 이 시험이 기존 안전 규칙에서 벗어나는 점 (승인 필요)
- 평소 구조는 Nav2 → `/cmd_vel_raw` → gate → `/cmd_vel`이다. 이 시험은 **gate를 거치지 않고** `limo_base`만 띄워 `/cmd_vel`에 직접 발행한다. 목적이 드라이버/MCU 동작 확인이라 Nav2와 gate가 끼면 원인이 섞이기 때문이다.
- 이 우회는 **바퀴를 띄운 벤치에서만**, 아래 속도·시간 상한 안에서만 쓴다. real launch와 gate는 수정하지 않는다.
- `allow_motor_drive:=true`는 쓰지 않는다(real launch를 실행하지 않으므로 해당 없음).

## 3. 시험 전 점검표 (하나라도 아니면 시작하지 않는다)
- [ ] 바퀴 4개가 바닥에서 떨어져 있다(받침대로 차체를 받쳤고 흔들리지 않는다). 바퀴 주변에 손, 케이블, 물체가 없다.
- [ ] 전원 스위치(또는 비상정지)에 손이 닿고, 누르면 끈다는 것을 확인했다.
- [ ] 사람이 둘 이상이면 한 명은 전원 쪽만 맡는다.
- [ ] 배터리 전압이 충분하다(`/limo_status`의 `battery_voltage` 기준, 기록한다).
- [ ] 다른 ROS 프로세스가 없다: `ps -eo pid,cmd | grep -E "[r]os2 launch|[l]imo_base"` 결과가 비어 있다.
- [ ] 격리 도메인 사용: `export ROS_DOMAIN_ID=77`. 팀 원본 `/home/pcu/capstone_ws`는 읽기만 하고 변경하지 않는다.
- [ ] 휴대폰으로 바퀴를 촬영한다(T3, T4의 정지 시각을 영상에서 읽기 위해).

## 4. 공통 환경 (터미널 3개)
모든 터미널에서 먼저:

```bash
source /opt/ros/humble/setup.bash; source /home/pcu/capstone_ws/install/setup.bash; source /home/pcu/capstone_experiment_ws/install/setup.bash; export ROS_DOMAIN_ID=77
```

- 터미널 A: `limo_base` 실행
- 터미널 B: 속도 관측
- 터미널 C: 명령 발행

속도·시간 상한: 선속도 **0.10 m/s 이하**, 각속도 0, 한 번의 발행은 **최대 3초**, 시험 사이에 **30초** 이상 쉰다. 상한을 올리려면 먼저 결과를 사용자와 검토한다.

## 5. 시험 절차

### T0. 기동과 정적 확인 (명령 없음)
터미널 A:
```bash
ros2 launch limo_base limo_base.launch.py
```
터미널 B:
```bash
ros2 topic echo --once /limo_status
```
기록: `motion_mode`(0이어야 4WD 차동), `control_mode`, `error_code`, `battery_voltage`.
기준: `motion_mode`가 0이 아니면 중단한다. 이때 `/cmd_vel` 발행자는 0개여야 한다(`ros2 topic info /cmd_vel`).

### T1. 영속 명령 없음 확인
터미널 B:
```bash
ros2 topic echo /odom --field twist.twist.linear.x
```
10초간 값이 0 근처로 유지된다. 바퀴가 도는 기색이 있으면 즉시 전원을 끈다.

### T2. 명령 중단 후 MCU 타임아웃 (질문 A)
터미널 B는 T1의 `/odom` 속도 관측을 그대로 둔다. 터미널 C:
```bash
ros2 topic pub -r 10 --times 30 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.10}, angular: {z: 0.0}}"
```
30개(약 3초) 발행 뒤 발행이 스스로 끝난다. 발행이 끝난 시각부터 `/odom` 속도가 0이 될 때까지의 시간을 잰다.

- 속도가 0.5초 안에 0이 된다: MCU가 명령 타임아웃으로 멈춘다. 시간을 기록한다.
- 속도가 0이 되기까지 0.5~3초 걸린다: 타임아웃이 길다. 기록하고, 3초 안에 멈추지 않으면 전원을 끈다.
- **0.10 m/s로 계속 돈다: MCU에 명령 타임아웃이 없다.** 즉시 전원을 끄고 이 시험을 중단한다. 이 경우 발행자(gate, Nav2, `limo_base`)가 죽으면 로봇이 마지막 속도로 계속 간다는 뜻이므로, 모터를 푸는 시험은 보류하고 별도 대책(예: 0 속도를 주기적으로 보내는 감시 노드, 하드웨어 정지)을 정한다.

반복: 3회, 각 회 사이 30초.

### T3. `limo_base`를 SIGINT로 종료 (질문 B)
터미널 C에서 발행을 계속하는 동안(`--times`를 두지 말고 3초 이내에 직접 중단):
```bash
timeout 3 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.10}, angular: {z: 0.0}}"
```
발행 시작 약 1초 뒤 터미널 A에서 Ctrl-C를 누른다. `limo_base`가 죽은 뒤(`/odom`이 끊긴다) 바퀴가 멈추는지, 몇 초 뒤인지를 영상으로 읽는다. 3초 안에 멈추지 않으면 전원을 끈다.

### T4. `limo_base`를 SIGKILL로 종료 (질문 C)
T3와 같은 발행을 하되, 터미널 B에서 다음 한 줄로 종료한다.
```bash
pkill -KILL -f "[l]imo_base/limo_base"
```
바퀴가 멈추는지 영상으로 읽는다. 3초 안에 멈추지 않으면 전원을 끈다.

## 6. 즉시 중단 조건 (전원을 끈다)
- 명령이 없는데 바퀴가 돈다.
- 명령(0.10 m/s)보다 확연히 빠르다.
- 발행이 끝났거나 `limo_base`가 죽은 뒤 3초가 지나도 멈추지 않는다.
- `error_code`가 0이 아니다.
- 바퀴가 받침대에 닿거나 차체가 움직인다.

## 7. 정리
- 터미널 A에서 Ctrl-C, 남은 프로세스가 없는지 확인한다(`ps -eo pid,cmd | grep -E "[l]imo_base"`).
- 기록은 이 파일 아래 표에 적고, 영상 파일은 정책상 저장소에 올리지 않는다(`docs/PUBLICATION_POLICY.md`).

## 9. 결과별 다음 단계
- T2~T4 모두 짧은 시간(예: 1초 이내) 안에 멈춘다: 워치독이 있다고 본다. 이 값을 gate의 `sensor_timeout_sec`(0.38 s)와 비교해 둘 중 어느 쪽이 먼저 막는지 문서화한다.
- T2에서 멈추지만 T3/T4에서 멈추지 않는다: 명령 타임아웃은 있지만 드라이버 소멸 시 문제가 있다는 뜻이다. `limo_base` 종료 시 정지 프레임을 보내도록 overlay에서만 수정하는 안을 따로 만든다(팀 원본은 수정하지 않는다).
- 모두 멈추지 않는다: 모터를 푸는 시험을 보류하고 대책부터 정한다.
- 어떤 경우에도 이 결과를 근거로 `allow_motor_drive:=true` 시험을 시작하려면 사용자가 별도로 승인한다.
