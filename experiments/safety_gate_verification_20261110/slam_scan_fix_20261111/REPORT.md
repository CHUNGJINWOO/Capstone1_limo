# SLAM 지도 갱신 불가: 원인 조사와 해결안 검증 (2026-11-11)

> **정리본 상태 (2026-11-11).** **검증 수준:** 원인은 실차 기록과 저장된 bag 재생으로 확인. 스캔 정규화는 **오프라인 검증**이며 실차 launch에는 적용하지 않았다. 실차 주행 중 정상 맵핑은 **미검증**. 이 기록은 당시 설정과 환경에서 얻은 값이며 이후 정리된 파일 이름·값으로 다시 측정한 것이 아니다. 전체 목록: `experiments/README.md`.

범위: 실차 모터 구동 없음. 읽기 전용 조사 + 기존 실차 rosbag 재생(노트북, 격리 ROS 도메인) + LiDAR 드라이버 단독 실행(LIMO, 구동계 없음). Git commit/push 없음, 팀 원본(`/home/pcu/capstone_ws`)·`ydlidar_ros2_driver`·Nav2·F4·Safety Gate 미수정. 실차 launch는 diff만 제시(적용 안 함).

## 1. 원인 (근거 수준을 구분)

**확인된 사실**
- Karto가 기대하는 읽기 개수는 `round((angle_max − angle_min) / angle_increment) + 1`이다(설치본 `karto_sdk/Karto.h:4307`, 360° 라이다만 `+0`). 이 값은 slam_toolbox가 **처음 처리한 스캔**으로 센서를 등록할 때 정해지고, 이후 개수가 다른 스캔은 `LaserRangeScan contains N range readings, expected M` 경고와 함께 거부된다(메시지는 `libkartoSlamToolbox.so`에 있고, 거부 동작은 아래 재생으로 확인; 소스 `.cpp`는 설치돼 있지 않아 코드로는 확인하지 못함).
- 실제 `/scan` 점 수는 한 값이 아니다(`ydlidar.yaml`의 `fixed_resolution: false`, 각도 ±110° 고정): 정상 상태 242/244/245개(예: 11/11 bag 2669개 중 87% 244, 8% 245, 5% 242), `angle_increment`가 그에 따라 0.015747~0.015907로 달라진다. 각도 범위(−1.91986~1.91986 rad)와 intensities(전 beam)는 고정/존재.
- **드라이버 시작 직후의 스캔은 더 짧다.** LIMO에서 드라이버만 5번 다시 켜서 첫 스캔을 기록: 첫 스캔 점 수 233, 235, 236, 236, 233개(이후 4~5개 스캔에 걸쳐 241~244를 거쳐 245 근처로 안정화). 이 값이 실제 실행 로그의 `expected`와 같다: 이번 세션 `expected 236`, 이전 실행들의 `expected 235 / 233 / 233 / 236`. 즉 기대 개수는 "시작 직후의 짧은 스캔"에서 정해지고, 정상 상태의 242~245개 스캔은 모두 거부된다.
- 기존 실차 기록으로도 재현된다: 팀의 이전 실차 bag 중 `/map` 토픽이 있는 25개 모두 `/map`의 알려진 셀 수가 처음과 끝이 같다(로봇 이동이 측정된 6개 포함: 휠 odom 2.1~6.0 m 이동). 우리 세션의 `/map`도 725셀로 고정(144회 덤프 모두 동일).

**재생으로 확인한 것**(노트북, 같은 slam_toolbox 2.6.10, LIMO와 동일한 파라미터, 실제 bag의 `/scan`+`/tf`)

| 데이터 | 입력 | 결과 |
|---|---|---|
| bag2 (F1B, 150 s) | 원본, 시작 스캔 주입 없음 | 등록 244 → 지도 784→4612셀 성장, 경고 1건(245 vs 244) |
| bag2 | 원본 + **실제 시작 스캔(233개)** 맨 앞에 주입 | **지도가 150 s 내내 720셀로 고정**, occupied 9, 경고 3건(244/245 vs **233**) ← 실차 증상 재현 |
| bag2 | 정규화 + 같은 주입 | 810→4251셀 성장, 경고 0 |
| bag3 (F4, 3.3×3.6 m 궤적) | 원본 + 시작 스캔 주입 | 14,269셀에서 34 s 이후 정지, pose graph 간선 약 13개, 경고 21건(244·242 vs 245) |
| bag3 | 정규화 + 같은 주입 | 33,101셀, 간선 약 44개, 경고 0 |

주의: 주입한 시작 스캔이 항상 "처음 처리된 스캔"이 되는 것은 아니었다(bag3 원본은 245로 등록). 어느 스캔이 먼저 처리되는지는 통제할 수 없으므로, 어떤 값으로 등록되든 거부가 생긴다는 점이 핵심이다.

| | A. `fixed_resolution: true` (드라이버 설정 사본) | B. SLAM 전용 정규화 노드 (`limo_scan_normalizer`) |
|---|---|---|
| 방식 | 드라이버 파라미터 사본으로 구동(원본 sha256 불변 확인), launch의 `params_file` 인자로 선택 가능 | `/scan` → `/scan_slam`(244 beam 고정), slam_toolbox의 `scan_topic`만 변경 |

| 기하 보존 | 정지 장면에서 원본과 per-angle 중앙값 차이 중앙 0.75 cm(원본-원본 반복 0.20 cm), 최적 각도 이동 0.00°, 90분위 141 cm(깊이 불연속 각도), 무효(echo 없음) beam 비율 29.0% vs 23~24% | 가장 가까운 원본 beam을 복사: 각도 오차 최대 0.454°(원본 beam 간격의 절반, 한계 이내), 보간·평균 없음 |

| 시작 스캔 문제 | 첫 스캔부터 263개라 해결될 것으로 보이나 모션 포함 SLAM 시험 없음 | 첫 스캔도 244개로 정규화 → 해결(주입 시험으로 확인) |

## 3. 정규화의 기하 보존 검증

- 합성 단위 시험 6종 통과(항등 격자, 236~251개 입력에서 Karto 기대값 항상 244, 가장 가까운 beam 복사와 각도 오차 한계, 무효 beam 유지·새 값 생성 없음, 범위 밖은 NaN, intensities·time_increment 정합).
- **실제 bag 스캔 4,167개 전수**: 실패 0건. 모든 출력 beam이 원본 beam의 값 그대로(복사), NaN/inf 새로 생기지 않음, 최대 각도 오차 0.454°(한계 비율 1.00), 스캔당 평균 원본 beam 0.09개 버려지고 0.10개 이웃 beam이 복제됨, 무효(≤range_min) 비율 입력 20.83% → 출력 20.81%. 유효하지 않은 거리를 장애물로 만들지 않는다. 범위 밖 beam은 NaN(거리 아님)으로 처리하지만 실제 데이터에서는 한 번도 발생하지 않았다.
- header(stamp·frame_id), `range_min/max`, `scan_time` 보존, `time_increment` 재계산, `angle_max = angle_min + (N−1)·inc`. ROS 노드 종단 시험(199개 입력/199개 출력): 모든 출력 244개, stamp 일치, Karto 기대값 = 길이.

## 4. 오프라인 지도 갱신 검증

- 경고 소멸: 정규화 재생 5건(정규화기를 263개로 둔 모사 1건 포함) 모두 mismatch 경고 0(원본 재생은 1~21건). 경고만 사라진 것이 아님을 아래 항목으로 확인.
- 스캔 처리: slam_toolbox가 발행하는 pose graph 간선(선분 마커 끝점 수의 절반, 수락된 스캔의 간접 증거) bag3 원본 약 13 → 정규화 약 44, 네이티브 244 전용 약 35. 원본은 34 s 이후 수락이 거의 멈췄다.
- 지도 성장: bag2 720 → 4251셀(고정 → 성장), bag3 14,269 → 33,101셀(77.4 m² 네이티브 244 전용 대비 82.8 m²).
- 실제 이동에 맞춘 확장: bag3 지도(정규화)는 기록된 궤적(F4 odom 3.3×3.6 m) 주변으로 원본보다 넓은 영역을 포함한다(하단 좌측 벽선, 우측 영역 등). 원본은 34 s까지의 일부만 가진다(`results/maps_b3_raw_vs_norm.png`: 빨간선이 기록된 궤적, 두 지도 모두 같은 위치에 벽 선분이 있다). 두 지도 모두 열린 공간 쪽으로 레이가 번진 흔적이 있어 방 전체가 깨끗하게 닫힌 지도는 아니다. bag2는 제자리 회전 위주(경로 2.49 m가 0.54×0.14 m 상자 안, 총 회전 4118°)라 "이동에 따른 확장"이 아니라 회전에 따른 확장이다.
- 장애물 형상 유지: (a) bag2에서 원본(정상 등록된 경우)과 정규화의 occupied 셀 평균 최근접 거리 3.7/3.4 cm(셀 5 cm). (b) bag3에서 변경 없는 244개 스캔만 쓴 지도(스캔 16% 제외)와 정규화 지도: 중앙 6.2 cm(양방향), 80분위 약 13 cm, 10 cm 이내 72%. 정규화 파이프라인을 두 번 돌리면 셀 단위로 동일하다(결정적). 지상 진실(ground truth) 지도는 없어서 "원본 기하와 얼마나 가까운가"만 말할 수 있고, 절대 정확도는 모른다.

## 6. 한계와 미확인

- 실차에서 정규화기를 켜고 로봇이 움직이며 지도가 성장하는지는 아직 시험하지 않았다(모터 구동 금지 + 미적용).
- 옵션 A를 모션과 함께 SLAM에 넣어 보지 않았다(정지 장면 기하 비교와 263개 모사만 수행).
- 지상 진실이 없어 지도의 절대 정확도·루프 클로저 품질은 평가하지 못했다.
- slam_toolbox 내부에서 "처음 처리한 스캔"이 정확히 어느 스캔이 되는지(TF·이동 게이트)는 소스 없이 추정이며 재생에서만 관찰했다.
- 재생은 실시간 배속(1.0)이고 원본 `/map`·위치(map→odom)는 비교에 쓰지 않았다(재생에서 새로 만들었다).
