## 4. Protective copy of the robot originals (proposal; needs your approval; nothing copied yet)
Scope: robot → laptop, **read-only on the robot**. Total about 7.9 GB: 11-13 runs 5.63 GB; 11-18 `run_004` and `run_004_bag_recovered_copy` 1.77 GB (plus the other 11-18 dirs, small); `20261119_run_001/002` 0.44 GB; recovery/diagnostic dirs; `limo_locked_stack`, `limo_robot_agent_field_20261120`, `maps_h107_20261120`, `limo-depth-observe` (≈ 16 MB).
Destination (new, never overwrites): `local_data/robot_originals_20261122/<source dir name>/` (git-ignored, same naming style as `robot_backups_*`). If a destination file exists, the copy stops for that file.
Procedure per run directory:
1. On the robot (read only): `find <dir> -type f -print0 | sort -z | xargs -0 sha256sum > ~/…/MANIFEST` is **not** written on the robot; the listing is streamed to the laptop over SSH instead (no new file on the robot).
2. `rsync -a --ignore-existing --protect-args pcu@<ROBOT_TAILNET_IP>:<dir>/ <dest>/` (no `--delete`, no `--remove-source-files`).
3. On the laptop: `sha256sum` every copied file and compare with the streamed robot list; compare file count and total bytes; mismatch = the directory is reported FAIL and copied again into a new directory name (never overwritten).
4. For every bag: `ros2 bag info`, SQLite `PRAGMA integrity_check`, and compare `message_count`, duration, file list with the robot's `metadata.yaml`.
5. Record: `run_guard` MANIFEST/FINISH, hash lists, `ros2 bag info` outputs, a table PASS/FAIL per directory, in `local_data/raw_results/real_limo_integ_claude_20261122/r0_copy_01/`.
6. The robot originals stay where they are; nothing is moved, deleted or modified; the copy does not start any ROS process and does not open the motor port.
Load on the robot: one sequential read of about 7.9 GB for the hashes and one for the copy; the robot's own state directories are not written. Duration estimate: tens of minutes on the direct Tailscale path (not measured).
11-18 `run_004` (and its recovered copy) are the most uncertain items: the laptop may hold a re-indexed copy under another name; the hash comparison will settle it.
