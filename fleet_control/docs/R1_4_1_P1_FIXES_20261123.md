# R1.4.1: two P1 safety fixes (2026-11-23, Claude; isolated/mock verification only)

Scope: the two defects reproduced by the Codex R1.4 independent re-audit (`local_data/raw_results/codex_r14_reaudit_20261123_AdGJNw/`, `REVIEW.md`, `probe.py`, `server-probe.py`). Not done: no real LIMO access, no deployment, no motor unlock, no change of the operating server 18190, no commit/push/PR. **This does not approve R4 motor-locked integration**, and nothing here verifies physical stopping.
Base state checked first: HEAD `c804241a`, G1 `0ca09dc4` (unchanged), `fleet_control/` still untracked on HEAD; the 278 `fleet_control/*` files listed in the Codex `SHA256SUMS` are byte-identical to the working tree before my edits (compared by hash), and nothing changed after the audit timestamp. Codex's own R1.4 edits (server `agent_contract_ok`/`agent_contract_valid`, `safety_protocol` partial check, mapping `allow_stop`, API.md R1.3 section, test fixture changes) are already in the working tree and were kept; no open Codex edit was seen (no file newer than the audit).

## 1. Root causes
**P1-1.** The server's hello reply carries `protocol_version` (service `hello`), but `AgentCore._hello` never read it, the state-reply loop never kept it, and `session_snapshot()` did not contain it. `compute_movement_permitted` checked the field only `if 'protocol_version' in ss`, so a snapshot without it (always the case) passed; the other session checks (boot, lease, freshness) were intact, which is why missing/null/bool/float/string/1 all reached `send_goal_async`.
**P1-2.** After Codex's R1.4 hardening, `worker_operation` called `_mapping_worker_robot(robot_id)` (contract required) before every action, so an Agent whose contract became incompatible got `409 agent_protocol` on `poll`; the operator's STOP was queued (its own path allows STOP) but could not be delivered.

## 2. Changes (files and functions)
| File | Change |
|---|---|
| `agent/.../safety_protocol.py` | new `SERVER_PROTOCOL_VERSION = 2`, new `server_contract_valid(ss)` (both versions present, exact `int`, equal to 2 and 1; bool/float/str/None/missing refused); used by `compute_movement_permitted` and by `check_active_goal_safety` (an active goal is cancelled with `SERVER_CONTRACT_INVALID` if the contract is lost) |
| `agent/.../core.py` | `AgentCore.__init__`: `server_protocol_version/server_protocol_boot`; `_hello`: cleared at start, stored raw from the reply and bound to the server boot of that reply; state-loop: cleared on server boot change / `needs_reconcile`, replaced if a state reply carries `protocol_version`; `session_snapshot()` returns `protocol_version` only while `server_protocol_boot == server_boot`, else `None` |
| `server/fleet_server/mapping.py` | `worker_operation`: contract mismatch ("stop_only") allows only: `poll` (returns a QUEUED STOP of the Agent's own boot, `renew` always false), then `accept`/`result` for that STOP (the existing command-id, session-id and boot matching still applies); everything else (`reserve_goal`, accept/result of any other command, other boots) -> `409 agent_protocol` |
| `tests/test_agent_safety_v1.py` | P2 (section 6) and synthetic session fixtures now carry `protocol_version` (they model a session the real hello produces) |
| new `tests/test_r1_4_1_agent_protocol_20261123.py`, `tests/test_r1_4_1_mapping_stop_20261123.py` | regression tests (section 4) |
No change to `ros_adapter.py`, `agent_node.py`, `http_api.py`, `service.py`, Gate Reset, Admission policy, Watchdog, or any Gate/Nav2 file. The Server's hello/state wire format is unchanged.

## 3. Command flow before and after
Before: hello (protocol dropped) -> state reply (lease, commands) -> `_on_command` -> `_do_nav` -> `compute_movement_permitted` (version not required) -> `send_goal_async`.
After: hello stores `(protocol_version, server_boot)`; every movement decision (`_do_nav` pre-checks and the active-goal monitor use `compute_movement_permitted` / `check_active_goal_safety` with `session_snapshot()`) requires `server_contract_valid`; a reconnect, a server boot change or a bad in-session value clears or replaces it, so an old approval cannot survive; cancel/STOP/read paths do not use it and stay available.
Mapping: operator STOP (queued) -> worker `poll` (was 409 under a mismatch) -> now delivered if it belongs to the worker's own boot -> `accept` -> `result` (server records the result event) ; no START/RESUME/PAUSE/SAVE, no goal reservation, no renew.

## 5. Safety of the STOP-only exception
Delivered only: command whose `action` is `STOP`, in the session whose recorded `boot` equals the polling Agent's boot (the Agent session itself is checked first by `check_session`), `QUEUED` once (an accepted STOP is not re-offered); accept/result must match command id, session id and boot (existing checks) and only STOP is allowed through; a result never rewrites an earlier one; a forged `START` result or accept is refused; `renew` is false so an incompatible worker cannot keep its session alive. Mapping is still limited to mock/sim Agents (`mapping_real_blocked` stays), and a silent worker still makes the session `UNKNOWN` (existing fail-closed). **Not verified:** that the worker physically stops anything, that the existing Watchdog/Gate/fence behave under a lost worker (unchanged code, not exercised), real ROS/DDS delivery.

## 6. P2 (test isolation) - independent of the P1 fixes
`test_agent_safety_v1` now (a) always installs its stubs, saving whatever was in `sys.modules` including already imported `limo_robot_agent.*` modules, (b) provides the `rclpy.clock` stub and `create_timer(**kwargs)` that the current `ros_adapter` needs (without them the suite did not even import: it failed identically on the G1 baseline and the current tree before this change), (c) in `tearDownModule` drops the stub-bound Agent modules and restores the saved ones. Assertions were not changed. 17/17 PASS without ROS and with ROS sourced; after teardown a fresh `ros_adapter` import binds the real `rclpy.node.Node` (checked).

## 7. Compatibility and deployment (Agent v4)
The server's wire format is unchanged: hello already returned `protocol_version`. Agent v4 on the robot is untouched (fix exists only in the working tree). A v4 Agent against the changed Server behaves as before (it never needed the new STOP path with a compatible contract). The new Agent checks stricter: against a Server that does not send `protocol_version` in hello the new Agent refuses movement (fail-closed), so Agent and Server must stay on the contract version 2 pair. Deploying the Agent change needs a new package (v5) through the existing deploy tool plus the isolated verification of the previous v4 procedure: not done and not approved.
