### 1.2 The 30-s abort condition: relation and verdict
The condition "Agent not online/reconciled within 30 s" is in my own runbook (`AGENT_V4_DEPLOY_PREP` §6); the user's approved abort list did not contain it. **It did not name a start point**, and the test harness did not enforce a 30-s timer: its wait loop allowed 120 s. Reading A (from the Agent process start): ≈ 1 s, satisfied. Reading B (from the script launch): ≈ 47 s, would have violated it.
**Verdict: the Agent behaviour = PASS; the pre-registered condition = UNDETERMINED (ambiguous wording, not enforced as a timer).** It was not exploited to hide a failure (the 47 s are fully explained by the precheck), but the record must not claim "within 30 s" without the start point. Correction (for the runbook and the harness): two clocks, `T_agent` = Agent process start -> reconciled ≤ 30 s, and `T_launch` = script launch -> reconciled ≤ 90 s when the precheck runs (≤ 45 s when it is skipped), both enforced by the harness.
