# 중앙 관제 웹 대시보드 사용 안내

이 문서는 **시험용 대시보드**(별도 포트·별도 데이터베이스·별도 토큰)를 노트북 브라우저에서 여는 방법과 화면 사용법을 설명합니다. 운영 중인 8080 서버와는 무관하며, 아래 내용은 모의 로봇(모의 Nav2) 기준으로 확인했습니다. 실제 LIMO에서의 화면 동작은 **UNVERIFIED**입니다.

## 1. 실행

영상·AI 실험 폴더의 `real_limo_kit/`에서 실행합니다(Git 밖 폴더, 토큰이 들어 있어 커밋하지 않음).

```bash
cd real_limo_kit
./00_gen_env.sh            # 최초 1회: .env 와 토큰(secrets/, 권한 0600) 생성. 토큰 값은 출력하지 않음
./10_start_ai_host.sh      # AI 호스트(YOLO, GPU) 시작
./11_start_dashboard.sh    # 대시보드 서버 시작
./12_sim_robot.sh start    # (실차가 없을 때만) 모의 로봇 + 모의 카메라 + 송신/수신 노드
./13_info.sh               # 주소와 토큰 파일 위치 확인(토큰 값은 출력하지 않음)
./50_stop_all.sh           # 끝낼 때: 이 스크립트들이 시작한 프로세스만 종료
```

`11_start_dashboard.sh`는 `.env`의 `FLEET_SRC`가 가리키는 체크아웃의 `fleet_server`를 사용합니다. 영상 패널은 이 체크아웃의 `server/fleet_server/static/video_panel.js`에 있고, 서버는 영상 서버 오리진을 `--video-origin`으로 받아 브라우저의 CSP `connect-src`에 추가합니다(옵션이 없으면 기존 CSP 그대로).

## 2. 접속 주소와 로그인

- 기본 주소(오늘의 시험): `http://127.0.0.1:18190/?video=http://127.0.0.1:18192` — `?video=`는 AI 패널의 영상 서버 주소를 미리 채웁니다(순수 오리진만 허용).
- 서버는 `127.0.0.1`에만 바인딩됩니다. 같은 노트북의 브라우저에서만 열립니다.
- **로그인 화면에서 "API 토큰 입력"에 대시보드 토큰을 붙여 넣고 [접속]을 누릅니다.**
  - 보기만: `secrets/fleet_viewer.token` (viewer)
  - 임무 생성·취소: `secrets/fleet_operator.token` (operator)
  - 토큰 값은 스크립트가 출력하지 않습니다. **본인 터미널에서** `cat secrets/fleet_viewer.token`으로 보고 선택·복사하세요(채팅·화면 공유·Git에 붙이지 마세요).
- 토큰은 그 브라우저 탭의 sessionStorage에만 저장되고 [토큰 지움]으로 지웁니다.
- **영상 패널은 다른 토큰을 씁니다**: `secrets/video_viewer.token`(영상 서버 viewer). 관제 토큰을 영상 서버로 보내지 않습니다.

## 3. 화면 구성 (위에서 아래로)

1. **로봇 카드:** 로봇 ID, ONLINE/OFFLINE, SIMULATED 배지(모의 로봇일 때), 마지막 수신, 위치(map 프레임 x, y, yaw), 지도 상태, Nav2, 배터리(전압만 있으면 백분율은 표시하지 않음), LiDAR, Depth 카메라, Safety Gate, 모터 출력 경로, 활성 임무, 연결 복구(통신 상태), 오류. 데이터가 없는 항목은 정상 값으로 채우지 않고 `NO_DATA`/`UNKNOWN`으로 표시합니다.
2. **지도와 로봇 위치:** 지도 위에 로봇(빨간 화살표, 방향 포함)과 임무 목적지(초록 원 + 임무 번호 끝자리)가 표시됩니다.
3. **임무:** 목적지 좌표 입력, 임무 생성, 임무 목록(상태, 남은 거리), 취소 버튼.
4. **AI 영상 (RGB + YOLO):** 별도 토큰으로 영상 서버에 연결해 실시간 영상과 검출을 표시합니다(아래 §5).
5. **이벤트 로그:** 로봇 온라인/오프라인, 지도·Nav2·LiDAR 변화, 임무 상태 변화가 시간순으로 쌓입니다.

## 4. 임무 생성과 취소 (operator 토큰)

1. 지도에서 목적지를 **클릭**합니다. x, y 칸이 자동으로 채워집니다(map 프레임, 위쪽이 +y). 직접 숫자를 입력해도 됩니다.
2. 로봇 선택을 확인하고 **[임무 생성 (NavigateToPose)]**을 누릅니다.
3. 목록에서 상태가 `DISPATCHED → ACCEPTED → EXECUTING`으로 바뀌고 "남은 거리"가 줄어듭니다. 지도에서 로봇 화살표가 움직입니다.
4. 실행 중에 행 오른쪽 **[취소]**를 누르면 `CANCELING` 뒤 `CANCELED`가 됩니다. 취소 완료는 로봇 쪽에서 실제 취소가 확인된 뒤에만 표시됩니다.
5. 이미 목적지에 도착했거나 끝난 임무의 취소는 효과가 없습니다(상태가 바뀌지 않음).
- viewer 토큰으로는 임무를 만들거나 취소할 수 없다고 화면에 표시됩니다.
- 로봇이 `RECONCILIATION_REQUIRED`이면 새 이동 임무는 만들어도 실행되지 않습니다(안전 장치). 복구는 admin 전용 API이며 이 화면에는 버튼이 없습니다([API.md](API.md) 참고).
- 모터가 잠금 해제된 실차에서의 임무 실행은 이 시험의 범위가 아니며 **UNVERIFIED**입니다.

## 5. 영상·YOLO 패널

1. 패널의 "영상 서버 주소"가 미리 채워져 있는지 확인하고(`?video=`), "영상 서버 토큰"에 **영상 서버 토큰**을 붙여 넣은 뒤 **[연결]**(또는 Enter)을 누릅니다.
2. 표시 항목: 상태 배지(수신 중 / 영상 끊김(정지) / 송신 측 연결 끊김 / 송신 측 없음), 주석 영상(박스·클래스·신뢰도), 검출 표(클래스, 신뢰도, bbox), AI 처리 연결, 수신 FPS, 수신 대역폭, 영상 지연(마지막 프레임 나이), 영상 전송 지연, 추론 지연(평균/p95), 호스트 처리 합계, 마지막 프레임 시각, 폐기(오래됨/덮어씀), 모델, 그리고 로봇 쪽 정보(텔레메트리: 로봇 CPU/RAM, 로봇이 측정한 왕복, 오래된 결과 차단 수, 두 장치 시계 오차 추정).
3. **오래된/끊긴 데이터는 현재 값처럼 보이지 않습니다.** 마지막 프레임이 2초보다 오래됐거나 상태가 `RECEIVING`이 아니면 영상 위에 "데이터 없음 / 오래됨" 표시가 뜨고 검출 표는 비워집니다. "검출 0개(수신은 정상)"와 "수신 실패"는 문구가 다릅니다. 영상 서버에 접속할 수 없으면 "영상 서버 연결 실패"입니다.
4. 영상 링크가 끊겨도 로봇 카드·지도·임무 기능은 별도 서버라 계속 동작합니다(모의 환경에서 확인: 송신을 끊은 상태에서 임무가 정상 실행됨).
5. RGB만 쓴 2D 검출이며 **거리(Depth)는 없습니다.** 검출 결과는 Nav2 costmap이나 Safety Gate에 연결되어 있지 않습니다.

## 6. 화면에 아무것도 안 보일 때

| 증상 | 확인할 것 |
|---|---|
| 페이지가 안 열림 | `./13_info.sh`로 대시보드 상태 확인, `./11_start_dashboard.sh` 재실행. 주소의 포트가 `.env`의 `DASH_PORT`와 같은지 |
| 로그인 후 "토큰이 올바르지 않습니다" | 대시보드 토큰(fleet_*)을 넣었는지(영상 토큰이 아님), 줄바꿈이 섞이지 않았는지 |
| "등록된 로봇이 없습니다" | 로봇 Agent가 서버에 접속하지 않음. 모의: `./12_sim_robot.sh start`와 `run/sim_agent.log` 확인. 실차: Agent 설정(`server_url`, 토큰)은 **UNVERIFIED** |
| 로봇이 OFFLINE | 마지막 수신이 6초 넘게 없음. Agent 프로세스와 네트워크 확인 |
| 지도 "NO_MAP" | 지도 업로드 지연(최대 몇 초). 계속되면 Agent 로그 |
| AI 패널 "영상 서버 연결 실패" | 브라우저가 영상 서버에 접근하지 못함. AI 호스트 실행 여부(`./13_info.sh`), 주소(`?video=`), 대시보드 서버가 `--video-origin`으로 시작되었는지(`11_start_dashboard.sh`는 자동으로 붙임) |
| "영상 서버 토큰이 올바르지 않습니다" | 영상 토큰(`video_viewer.token`)을 넣었는지 |
| "송신 측 없음/끊김" | 송신 노드가 안 돌고 있음. 모의: `run/sim_sender.log`. 실차: [REAL_LIMO_VIDEO_TEST.md](REAL_LIMO_VIDEO_TEST.md) |
| 영상은 오는데 "데이터 없음 / 오래됨" | 프레임 나이가 2초 초과. 네트워크 지연/과부하. 지표는 `./40_record_metrics.sh`로 기록 |

## 7. 알려진 한계

- 오늘의 시험은 한 대의 노트북, 모의 로봇, 재생 카메라 소스(또는 Gazebo 라이브)로만 확인했습니다. 실차, 실제 Tailscale 구간, 장시간 운용은 **UNVERIFIED**입니다.
- 브라우저 화면의 검증은 사람이 보는 화면 기준의 자동 조작으로 한 번 수행했고, 모든 해상도·브라우저 조합을 확인하지는 않았습니다.
- HTTP는 TLS가 없습니다. 노트북 로컬(루프백)에서만 사용하고, 원격에서 열 때는 Tailscale 같은 사설망만 사용하세요.
