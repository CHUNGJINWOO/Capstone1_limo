# 고아 번들 진단과 복구 제안 — 운영 복구 미구현

`fleet_server.orphan_diagnostics.diagnose_orphans(db_path, bundle_root)`는 체크포인트 완료된 **오프라인 DB 스냅샷**과 쓰기가 중단된 번들 사본만 진단한다. SQLite immutable 모드이므로 nonempty WAL이 있는 DB는 거절한다. 호출 중 원본이 바뀌면 일관된 관측이 보장되지 않는다. `MapRegistry()` 생성은 마이그레이션·디렉터리 생성을 하므로 운영 데이터 진단에 사용하지 않는다. 기존 `reconcile_storage()`는 staging을 지우므로 읽기 전용 함수가 아니다.

진단은 manifest·파일·계산된 지도 ID·번들 해시·저장 키와 DB 지도 ID를 비교하고 응답 기록의 참조 여부를 제시한다. 개별 파일의 링크를 거부하며 posegraph는 스트리밍 해시한다. 파일 무결성은 생산자·소유권·지도 안전성·원본 진위를 증명하지 않는다. 보고된 `recovery_allowed`는 항상 false다. 문자열 검색으로 발견한 멱등성 기록은 참고 정보이며 인증된 출처 증거가 아니다.

| 분류 | 향후 처리 제안 |
| --- | --- |
| INTACT_UNVERIFIED_ORIGIN | 출처 확인 전 등록 금지. 운영자 확인과 독립 백업, manifest·원본 증거 및 지도 충돌 검토 후에만 별도 승인된 절차 설계 |
| CORRUPT_OR_UNSAFE | 재등록 금지. 증거 보존 후 관리자 검토; 자동 격리하지 않음 |
| DUPLICATE_REGISTERED | 기존 등록 지도 무결성·소유권 확인. 중복 파일을 임의로 지우지 않음 |
| ID_CONFLICT | 재등록 금지. 다른 기하·층·번들 가능성 검토 후 별도 ID 정책 결정 |
| STAGING_UNREVIEWED | 진행 중 업로드 또는 중단 파일일 수 있음. 스냅샷과 백업을 남기고 경과·소유자 확인; 자동 삭제 금지 |

모든 상태에서 복구 실행은 미구현이다. 재등록·격리의 구현 전에는 관리자 승인, 변경 전후 DB·바이트 해시와 감사 이벤트, 잠금·재시작 후 중복 방지, 중간 실패 롤백 및 백업 복원 시험을 별도로 마련해야 한다. 재등록 시 지도는 UNVERIFIED로 남으며 활성 포인터·로봇 상태는 바꾸지 않는다. 동일 파일 업로드는 현재 고아 저장 경로 충돌로 409다. 진단 결과만으로 고아를 덮어쓰거나 자동 채택해서는 안 된다.

## 자원 및 시간

기존 두 48 MiB 근접 JSON 요청에서 별도 서버 RSS 27.3→322.1 MiB가 관측됐다. 본문 청크와 결합 결과, UTF-8 문자열·JSON 객체, base64 디코딩 및 해시 준비가 동시에 메모리를 사용한다. 입력 슬롯 2개는 프로세스 전체 메모리·대기 스레드 수의 상한이 아니다. 큰 요청에서 10초 전체 수신 제한은 느린 정상 연결도 408로 거절할 수 있다. 작은 서버에서는 OOM으로 프로세스가 종료될 가능성이 있으며 현재 안전한 자동 거절을 보장하지 않는다.

향후 API 호환 방향은 단계적 파일 스트리밍·증분 base64 검증, 슬롯 대기 스레드 제한 또는 프록시 연결 제한, 서버별 메모리 예산 및 시간 제한의 실측 기반 설정이다. 서버 운영 설정을 이번에 변경하지 않는다. 진단의 YAML/PGM 상한은 기존과 같고 큰 posegraph는 청크 단위 해시하나, PGM canonical 변환의 피크 메모리는 별도 측정이 필요하다.
